# GitHub delivery automation

- `CI` runs policy, quality, integration and containers on every PR to develop/main and every push to either. `required` fails when any gate fails or skips. The four observed GitHub Actions checks (`policy`, `quality`, `integration`, `containers`, App 15368) are required on both branches with strict up-to-date checking. No path filters bypass the gate.
- CODEOWNERS names `@weaves-app/weave-maintainers`. Rulesets require review. The requested develop-quality team bypass remains; maintainers must not use it to hide failures.
- PRs into develop require `feat|fix|bugfix|hotfix/WEA-N/slug`, matching imperative Conventional Commit title, Linear/spec/evidence links, and current develop ancestry. Same-repository develop alone may enter main. Release PRs use merge commits to preserve ancestry; feature PRs use squash.
- Configure squash message as title only to keep one-line commit messages. Main release merge commits are a documented GitHub-generated exception to authored Conventional Commits; classification reads non-merge commits.
- After successful push CI, `Publish images and releases` publishes API/web multi-architecture SHA images to GHCR. Develop receives no SemVer tag/release. A main push computes one shared workspace version (first feature: 0.1.0), creates version aliases, Git tag, GitHub release, changelog and JSON manifest with immutable digests and Linear links. Any non-feature/non-breaking shipping change increments patch; `feat` increments minor and `!` increments major. Package manifests remain 0.0.0 placeholders; official version is the Git tag/release manifest.
- Changelog is generated from actual shipped commits and attached to the release, with no bot commit back to protected main. A batch release is the contents of develop when its PR merges into main. Keep unfinished behavior behind feature flags; do not routinely cherry-pick subsets.
- Release concurrency serializes publication. A rerun for an already tagged commit fails before image rebuild. Inspect failed partial publication before retrying; recover published digests instead of overwriting an official version.
- `Promote released image aliases` takes an existing version and QA/production target on main. It loads the release manifest, retags the exact digests and verifies identity. It does not build or increment SemVer. After a main release, QA promotion runs automatically, then production waits for the maintainer environment approval. Manual dispatch is available for recovery/rollback to an existing release.
- Registry alias promotion is implemented; AWS provisioning/deployment, runtime secrets, ECR/GHCR choice, domain/TLS and Linear release API credentials await a separate environment decision. Docker images can run on an EC2 VM or ECS; EKS is not required. Native mobile installation/store publication uses signed native artifacts, not these server containers.
- Version tag update/deletion protection is enabled separately in GitHub. Tag creation restriction requires an identified dedicated GitHub App; do not lock out GITHUB_TOKEN releases by guessing an actor. GITHUB_TOKEN currently publishes releases; restrictive creation permissions remain an explicit follow-up.

GitHub workflows use read-only permissions for PR code. Publication runs only after successful same-repository push CI, never untrusted PR workflow runs. Fork contributions cannot enter shared branches under the current source policy. Packages use repo-scoped GITHUB_TOKEN; no personal tokens are committed.

The audit report is uploaded by CI as informational output. Current Expo/Jest and Prisma transitive findings have no compatible non-breaking fix from npm; no force downgrades or blanket overrides are applied. See `dependency-security.md`. This does not certify a production-ready security posture.

QA/production environments are restricted to main. Production requires a maintainer review, prevents self-review and disallows admin bypass. Because develop is the default branch, the workflow_run publisher dispatches promotions explicitly at main; checkout alone would not change an environment deployment ref.

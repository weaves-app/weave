# Starter component catalogue

Shared `@weave/design-tokens` defines semantic colors, spacing and radius. Web applies them as CSS variables; native uses them through StyleSheet. Keep platform-neutral values in this package and reuse variants rather than copying styles.

| Native primitive | Variants                                  | Accessibility                                                                                                  |
| ---------------- | ----------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Button           | Primary, outline, text; disabled, loading | Button role, explicit label, busy/disabled state, minimum 48-point target; inactive states never invoke action |
| Screen           | Content wrapper                           | Safe-area container, consistent spacing/background                                                             |

The starter is a technical scaffold, not an approved product design. Before feature UI, specify typography/spacing, hierarchy, light/dark behavior, responsive/safe-area behavior and loading/empty/error/disabled states. Expand the catalogue with reviewed examples. Reuse primitives when semantics match; avoid a universal component full of unrelated flags. Platform renderers remain separate.

WEA-10 adds native `FormField` (visible/accessibility label, secret entry, email/code keyboards, disabled editing, minimum48-point height) and `Feedback` (alert role, polite live-region announcement, busy state). Login composes these with Button/Typography inside safe-area and keyboard-aware scrolling. Home has a single Logout action with pending/failure feedback. Recovery owns its safe-area context and reuses primitives without auth/navigation dependencies. Device VoiceOver/TalkBack, enlarged text and focus behavior still require recorded validation; component assertions are not device evidence.

The owner-supplied brand kit is retained in `assets/brand` with its [guidelines](../../assets/brand/guidelines.md) and Figtree license. Shared tokens now use cream background, olive foreground/primary, linen borders, terracotta accent and sage support. Terracotta is reserved for graphics/accents, never small text. Native primitives select bundled Figtree Regular/SemiBold/Bold; web loads the local variable font. `BrandLogo` renders the supplied outlined horizontal lockup with aspect-preserving sizing and proportional one-band clear space. Login places it before the existing heading; Home retains its single Logout action. The ambient image module's default export is a Metro asset convention, documented as a framework boundary. Asset sizes, app icon opacity and adaptive masking are recorded in the brand README.

The approved WEA-10 login refinement adds `BrandLogo` width/alignment options, compact `Typography` heading/supporting/label/caption variants, `FormField` placeholder/autofill hints and focus styling, and primary/outline/text `Button` variants with optional decorative content. All interactive variants retain labels and disabled/busy states and a minimum 48-point target. `AuthMethodTabs` announces the selected password or email-code method. `CodeField` uses one real six-digit native input behind six passive visual slots; formatted paste is normalized before limiting length, and visual focus/caret follows the native insertion point or selected range without restricting normal editing. It requests one-time-code autofill, retains normal editing semantics, and uses a visible single field when native font scaling reaches 1.5. Login/OTP share keyboard-aware scrolling, safe-area padding, semantic feedback and submit/resend controls. Complete six-digit verification input automatically verifies through the existing controller; partial codes remain editable and pending disables duplicate attempts. Password/email-code switching uses a local measured transition with a stable scroll extent, excludes hidden password input from touch/accessibility and honors Reduce Motion. Component hints do not prove delivered-code autofill or full screen-reader acceptance.

WEA-10 T052 uses one feature-local authentication header above the keyboard-aware scrolling form. Login and email/device verification render the same centered 128-point BrandLogo; equal navigation slots preserve its horizontal position. Verification Back is a 48-point control at the top-left inside the safe area, disabled while pending. The header stays visible while the form scrolls or the keyboard opens.

T053 adds a centered shared authentication frame for tablet-width windows (600 points and wider), bounded to480×740 points. Login and verification headings share one top-aligned scroll origin under the fixed header; OTP has no extra decorative leading offset. Narrow windows use the full safe area. Form scrolling handles short viewports, keyboards and enlarged text; pending/error changes do not recenter the frame.

T054 extracts feature-local `AuthLayout`: phones (short dimension below600 points) stay top-aligned in both orientations; portrait tablets center the shared bounded frame; landscape tablet windows at least960 points wide show decorative bag artwork and a tagline beside the cream authentication pane. The same form subtree persists across rotation, preserving entered email and partial code. The artwork is excluded from accessibility, the tagline remains text, and keyboard/enlarged-text scrolling stays inside the form pane.

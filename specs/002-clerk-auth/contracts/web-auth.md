# Current public web contracts

Routes: `/` protected Home; `/sign-up` public email/password and Google; `/sign-in` email/password and Google; `/sso-callback` Clerk SSO completion. `/invite` is absent (404); legacy invitation query parameters do not create an invitation screen. Invitation/settings/organization management is deferred.

Protected `/api/session` returns a minimal authenticated result, 401 signed-out/invalid/unverified, or 503 unavailable configuration/provider; `Cache-Control: no-store`. Every resource independently guards access. Clerk callback completion navigates to this protected Home boundary; incomplete flows return to signup/signin, and callback offers a return-to-signin recovery link.

Current AuthGateway operations: signup(email,password), signin(email,password), google(mode), sendCode(mode), verify(mode,code), current(mode), activate(mode), deactivate(). Historical invitation port/policy remains internally for preserved prior work but no public route/UI uses it. Google starts the official `sso` API with `oauth_google`, `/` final destination, and `/sso-callback` incomplete-flow destination. Initiation never reports a local successful account or activates a fake session. Unknown provider failures map to safe retry messages. One in-flight operation guards Google and password submission together.

Public UI: approved brand shell with bag/wordmark/Figtree/OFL, semantic web auth tokens and favicon, labelled email/password/code, disabled pending submits, status/alert feedback, resend/start-again, links between signup/signin, existing Home/signout. No demonstration toolbar, organization APIs or invitation form.

Regression contracts: AuthFlow.rebind preserves error/pending state through SDK updates. OAuthGateway.finish returns a destination only after provider completion, a continuation for supported verification, or an explicit recovery message; repeated callback resolution shares one attempt. Callback view waits for Clerk browser readiness, catches rejections and bounds unresolved operations. Pending session tasks cannot show credentials or Home; organization membership prerequisites are explicit and signout is available. No organization requirement is bypassed.

## Approved organization revision (supersedes earlier direct-Home/deferred-onboarding text)

Fresh email or Google authentication completes at /organizations. ClerkProvider taskUrls routes choose-organization to the same picker. /organizations/create is the approved create form. Signed-out picker access returns to /sign-in. Onboarding may read Clerk pending identity solely to handle choose-organization; other tasks and unverified identity are denied. Home and /api/session require verified identity, active organization, and non-pending session; pending or missing-organization Home access redirects to the picker, API denies access. No app-invitation route or invitation management is introduced.

OrganizationGateway list/accept/create/activate is a consumer-owned contract. OrganizationFlow exposes observable list, selection, loading/pending/error/created state and cancel. The SDK composition loads all membership and pending invitation pages, merges by organization ID, prefers memberships, and accepts only an invitation retrieved for the current user. Activation verifies the SDK session is active with the selected organization and no remaining task before Home navigation. Creation uses Clerk’s administrator role, displayed as Administrator; the preview’s Owner wording does not invent a separate unsupported role. List and mutation requests time out; cancellation invalidates late navigation. Retry after known creation success reuses the created organization.
